# Irodori Speaker Studio

複数の音声ファイルを読み込み、文字起こし・文脈に沿った分割・DACVAE変換・
Irodori-TTS **v4 Large** のSpeaker Inversion学習まで実行する日本語GUIクライアントです。
Pythonソース版です。Windowsのコマンドプロンプトで直接起動できます。WSL2は不要です。
Linux/RunPodの起動にも引き続き対応します。

## できること

- WAV / MP3 / FLAC / M4A / OGG / WebM / AACを複数まとめて投入。
- faster-whisperで日本語の文字起こしと単語タイムスタンプを取得。
- **5〜10秒は目安。文脈を優先し、長い文を時間だけで切りません。**
- 文末の句読点を使って分割。短い隣接文は目安の範囲内でまとめます。
  句読点が得られない場合は発話の間を境界候補にします。
  長い無音を挟む発話や、単独の短い文はそのまま保持します。
- 秒数外の素材も自動的に学習対象に含めます。「使用」をOFFにして個別除外可能。
- 音声を試聴し、開始/終了秒と文字起こしを編集可能。
- 「分割して確認」「分割から学習まで一括実行」の2モード。
- v4 Largeの非量子化モデルを初回に取得。ローカルモデル指定も可能。
- 公式DACVAEの正規化（-16dB）と決定的エンコードを使用。
- モデル本体を固定し、16個の話者埋め込みトークンだけを学習。
- 途中停止、保存プロジェクト再読込、保存済み話者埋め込みからの追加学習。
- 分割音声、JSONLマニフェスト、潜在表現、学習結果をZIPで取得。

## 必要環境

- Windows 10/11の64ビット版、またはUbuntu/Linux。
- 学習にはNVIDIA CUDA GPUとBF16対応が必要。音声分割はCPUだけでも可能です。
- CUDA 12.8版PyTorchを使用できるGPUドライバー。
- Pythonとuv、インターネット接続。モデルと依存パッケージは初回に取得します。
- モデル、パッケージ、音声、潜在表現を置ける十分なディスク空き容量。
- GPUメモリ必要量は素材の長さにも依存します。特定GPUでの完走は未検証です。

## Windowsでの導入（WSL2不要）

1. ZIPを展開します。以前の版を使っている場合は、展開した内容でプログラムを更新してください。
   既存の `projects/` は消さずに残してください。
2. Pythonとuvは、すでにインストールしてあるものを使えます。
   初めて使う場合は64ビット版Pythonを導入し、`python -m pip install uv`を実行してください。
3. `git --version`でGitが見つからない場合は、Git for Windowsを導入してコマンド画面を開き直します。
   https://git-scm.com/downloads/win
4. `setup.bat`をダブルクリックします。初回はモデル以外の依存パッケージを取得するため時間がかかります。
   画面に進捗を表示し、同時に `setup.log` へ保存します。
5. 完了したら `start.bat` をダブルクリックします。ブラウザーが開きます。

コマンドプロンプトから実行する場合（配置場所が `G:\irodori-speaker-client` の例）:

```bat
cd /d G:\irodori-speaker-client
setup.bat
start.bat
```

以前使った次のコマンドも、Windowsで直接実行できるようになりました。

```bat
python3 setup_client.py
```

学習用にはuvが専用のPython 3.11環境を用意します。普段使っているPythonのバージョンは変更しません。
起動後のURLは **http://127.0.0.1:7865** です。自動でブラウザーが開かなければ手動で開いてください。

環境を再確認したい場合は `check_environment.bat` をダブルクリックします。
依存パッケージの読み込み、GPU/BF16計算、公式train.pyの起動を確認します。
CUDA GPUが見つからない場合、CPUの音声分割は利用できますが学習は実行できません。
NVIDIAドライバーはWindows側で更新してください。

今回の音声分割・学習はPyAVとSoundFileで音声を扱うため、外部FFmpegは必須ではありません。
別途公式 `infer.py` の音声入出力を使う場合はTorchCodecがFFmpegのshared DLLを必要とすることがあります。
その場合はshared版FFmpegのbinフォルダーをPATHへ追加してください。
Windows用TorchCodecの要件: https://github.com/meta-pytorch/torchcodec#installing-torchcodec

### Windows版の変更

- `setup.bat` / `start.bat` / `check_environment.bat` を追加。
- Windowsの `.venv\Scripts\python.exe` を使用。
- 日本語ログのUTF-8入出力を指定。
- 学習は親workerを残したまま起動し、停止時は `taskkill /T` で学習プロセスも停止。
- 空白を含むパスをコマンド文字列へ展開せず、Pythonの引数配列で扱います。
- 公式依存関係は凍結されたuv.lockを使い、Python 3.11・CUDA 12.8を導入。

## Linux / RunPodでの起動

ZIPを展開し、このREADMEのあるフォルダーへ移動します。

```bash
python3 -m pip install uv
python3 setup_client.py
bash start.sh
```

UbuntuのシステムPythonでpipの利用が制限される場合は、先に仮想環境を作ります。

```bash
python3 -m venv .bootstrap
.bootstrap/bin/python -m pip install uv
PATH="$PWD/.bootstrap/bin:$PATH" python3 setup_client.py
bash start.sh
```

`venv`がなければUbuntuの`python3-venv`パッケージが必要です。
セットアップは同梱した公式リポジトリのCUDA 12.8依存環境を作り、その環境へ
GUIと文字起こし用の依存パッケージを追加します。Python 3.11はuvが用意します。

起動後、ブラウザーで **http://127.0.0.1:7865** を開きます。

RunPodでは、このフォルダーとモデルキャッシュを永続化される場所へ配置してください。
Pod上にクライアントを置き、ブラウザーから音声をアップロードする構成です。
手元PCからSSHで学習コマンドを送る別エージェント方式は含めていません。

SSHポート転送を利用する場合は、Pod上で通常起動したうえで、手元PCから
次の形式で接続し、手元の http://127.0.0.1:7865 を開きます。

```bash
ssh -L 7865:127.0.0.1:7865 -p <SSHポート> root@<Podの接続先>
```

RunPodのHTTPポート公開を使う場合は、7865を公開し、起動前に認証を設定します。

```bash
export IRODORI_USER='studio'
export IRODORI_PASSWORD='<自分で設定したパスワード>'
bash start.sh --host 0.0.0.0 --port 7865
```

ホスト名やポート、公開URLはPodの接続画面で確認してください。
外部公開時は認証の設定を必須にしています。通常のローカル起動は認証なしです。
このクライアントは単一ユーザー向けです。

## 操作手順

1. 同じ話者の音声ファイルを複数選択します。
2. モードを選び、「開始」を押します。
3. 確認モードでは、一覧の文字起こし・切り位置を修正します。
   「修正を保存」を押した後、試聴クリップを選ぶか「試聴を更新」を押してください。
4. 「修正を保存して学習」を押します。一括モードなら確認待ちなしで進みます。
5. 学習終了後、結果ZIPをダウンロードします。

初期値はWhisper large-v3、文字起こしCPU、学習3000ステップ、学習率0.01、
バッチ1、勾配蓄積1、Gradient Checkpointing ON、BF16です。
CPUでのlarge-v3文字起こしには時間がかかります。速度優先ならsmall/mediumを選べます。
Whisper CUDA実行にはCUDA 12のcuBLASとcuDNN 9が必要です。
GPU文字起こしのライブラリーエラーが出る場合はCPUを選択できます。

「v4 Largeモデルのパス」は**実行しているPC上のパス**です。
空欄なら `Aratako/Irodori-TTS-v4-Large` の `model.safetensors` を取得します。
量子化モデルやSmallモデルは学習には使用できません。

## 分割の考え方

音声の意味を完全に理解する専用モデルではなく、Whisperの文字起こし・句読点・
発話間隔から文のまとまりを推定します。文末が認識できればその文の途中では切りません。
句読点が得られない連続発話では、5〜10秒を超えても保持する場合があります。
認識の誤りや句読点の欠落で境界がずれる場合は、GUIで切り位置を直せます。
長い無音や認識されなかった非発話部分は学習素材に含めません。
認識できる発話がないファイルはログとwarnings.jsonに記録します。

目安の秒数外の素材、文字起こしの確信度が低い素材、30秒超の素材には確認メモを付けます。
秒数外という理由で削除したり、固定秒数で強制的に切ったりはしません。
長い音声はGPUメモリ使用量が増えます。

## ターミナルの進捗表示

`start.bat`で開いたターミナルにも、文字起こし・分割・DACVAE変換・学習のログを表示します。
工程の開始/完了/停止/失敗と経過時間が分かります。学習スクリプトの標準出力と
エラー出力もそのまま表示します。
ログが15秒間出ない場合は「実行中」と経過時間を表示します。
これは進捗率や終了予定時間ではなく、プロセスが実行中であることを示す表示です。

ログは引き続き画面内の進捗欄と `projects/<ID>/run.log` に残ります。
更新時は現在の処理が終わってからクライアントを終了し、ZIPを上書き展開して
`start.bat`で再起動してください。このログ更新だけならセットアップのやり直しは不要です。

## 保存と追加学習

データは `projects/<プロジェクトID>/` に保存されます。
再起動後は画面にIDを入力し「保存プロジェクトを開く」を押すと編集を続けられます。
保存場所は起動時の `IRODORI_JOBS` 環境変数で変更できます。

```text
projects/<ID>/
  input/             取り込んだ元ファイル
  sources/           48kHzモノラルへ変換した元音声
  clips/             分割WAV
  rows.json          境界・文字起こし・採否
  latents/           DACVAE潜在表現
  manifest.jsonl     公式train.py用入力
  train_large_speaker.yaml
  output/<実行ID>/   学習済み話者埋め込み
  training.json      最新の学習出力先と基盤モデル
  provenance.json    学習条件と公式コードのバージョン
  run.log
```

再学習は新しい実行IDのフォルダーへ保存され、以前の学習結果は残ります。
停止時も素材と保存済みチェックポイントは残ります。

### 保存して中断・PC再起動後の再開

今回の版では、Speaker Inversionの埋め込みだけでなく、オプティマイザー、
スケジューラー、ステップ番号、Python/PyTorch/CUDAの乱数状態、データローダー位置、
モデルバッファーを保存します。同梱の公式train.pyにStudio専用の拡張を加えています。

1. 学習中に「保存して中断（学習中）」を押します。
2. 現在のオプティマイザーステップが終わり、状態の保存が完了するのを待ちます。
   勾配蓄積を使っている場合は、その一組が終わるまで待ちます。
3. **「学習状態を保存して中断しました」の表示後**にブラウザーやターミナルを閉じ、
   必要ならPCを再起動します。
4. `start.bat`で起動し、「保存済みプロジェクト」から選択します。
5. 「保存プロジェクトを開く」を押し、**「保存状態から再開」**を押します。

再開時は文字起こしやDACVAE変換をやり直しません。総学習ステップ数も元の値を使います。
例えば3000ステップの学習を1037で中断すると、1038から3000まで続けます。
「追加学習する埋め込み」の欄を入力する必要はありません。
「修正を保存して新しい学習」は別の学習を開始するボタンです。

保存先は `output/<実行ID>/resume_state.pt`、ステップ情報は `resume_info.json` です。
再開用ファイルは250ステップごと（総ステップ数が250未満ならその間隔）、
保存して中断時、学習終了時に更新します。更新は一時ファイルからの置換で行い、
書き込み失敗時も以前の再開用ファイルが残るようにしています。
中断時の話者埋め込みは `checkpoint_pause.speaker.safetensors` としても保存します。
通常の250ステップごとの埋め込み出力は引き続き保存します。

完全再開は同じ基盤モデル、素材、学習設定、コード、GPU、PyTorchバージョンで行ってください。
基盤モデル・潜在表現・設定のSHA-256を確認するため、開始と再開時に時間がかかる場合があります。
プロジェクト、モデル、仮想環境のフォルダーは元の場所に残してください。
学習中に素材を修正したり変換し直したりすると、完全再開の一致確認で拒否します。

**この更新より前に実行していた学習には、完全再開用の状態がありません。**
既存の.speaker.safetensorsからは、従来どおり「追加学習」で引き継げます。
追加学習は新しいオプティマイザーとステップ数で始めます。

保存完了前のターミナル強制終了、電源断、強制停止では、未保存の学習分は復元できません。
その場合は最後に保存したresume_state.ptからの再開になります。
「保存して中断」は単一GPU・ワーカー0・先読み無効の構成に対応します。
任意の計算途中をメモリごと保存する機能ではなく、完了した学習ステップの境界で保存します。

CPUの小規模テストでは、別プロセスでの再開（エポック境界を含む）で、
中断なしの実行とパラメーターがビット単位で一致することを確認しました。
ただし、v4 Largeの実GPU学習での中断・再開は未検証です。
CUDAの非決定的な演算があるため、保存状態を復元してもGPUの将来の計算結果が
ビット単位で一致することまでは保証しません。

## 学習した声を使う

ZIP内の `output/<実行ID>/checkpoint_final.speaker.safetensors` が話者埋め込みです。
学習に使用した同じv4 Large基盤モデルと組み合わせて使います。
`training.json`にその基盤モデルのパスを記録しています。

```bash
irodori/.venv/bin/python irodori/infer.py \
  --checkpoint <学習で使用したv4-Largeのmodel.safetensors> \
  --ref-embed <checkpoint_final.speaker.safetensorsのパス> \
  --text 'こんにちは。学習した声のテストです。' \
  --output-wav sample.wav
```

## 公式コードとの対応

同梱の `irodori/` は以下の公式コミットを基にしています。
`train.py`のSpeaker Inversionに状態保存・再開・中断のフックを追加し、
`studio_state.py`を追加しています。この拡張は公式の機能ではありません。

- 公式: https://github.com/Aratako/Irodori-TTS
- コミット: `89f9d8fbd4d51ea019867ee1197725ede1df13c5`
- 基盤モデル: https://huggingface.co/Aratako/Irodori-TTS-v4-Large
- 文字起こし: https://github.com/SYSTRAN/faster-whisper

v4 Large専用のSpeaker Inversion YAMLがこの公式版にはないため、
公式Speaker Inversion設定の学習セクションを使い、**モデル構造はLargeチェックポイントの
config_jsonメタデータから取得**します。Smallのモデル寸法は流用しません。
チェックポイントに含まれるduration predictorの構造も保持します。

文脈を優先した長い素材が公式Datasetの長さ制限で切り捨てられないよう、
max_latent_stepsは実際の最長潜在表現、max_text_lenは実際の最長トークン数に合わせます。
音声変換と学習は公式API/公式train.pyを使用します。

### プロジェクト名と出力名

画面上部の「プロジェクト名」に任意の名前（日本語可）を入力して開始できます。
保存済みプロジェクトは選択して「保存プロジェクトを開く」で読み込み、名前を入力して
「プロジェクト名を保存」で変更できます。名前未設定の旧プロジェクトにも対応します。

例：プロジェクト名が「みあ」の場合、250ステップの出力は
`みあ_0000250.speaker.safetensors`、中断時は `みあ_pause.speaker.safetensors`、
最終出力は `みあ_final.speaker.safetensors` です。空欄なら従来の `checkpoint_...` です。
変更時は現在の学習出力も改名します。過去の別の学習回の出力名は保持します。
フォルダは `projects/<管理ID>/output/<学習回ID>/` のままです。
名前変更では学習済み埋め込みやオプティマイザー状態を変更しません。
処理中は名前を変更できません。保存して中断または完了してから変更してください。
Windowsのファイル名に使えない文字（`\ / : * ? " < > |`）、予約名、末尾のピリオド、
80文字を超える名前は入力エラーになります。同じプロジェクト名も使用できます。

更新時は実行中の処理を保存して中断または完了し、アプリを終了してから上書きしてください。
`projects` と既存の仮想環境は保持してください。

### 分割完了後に素材一覧が表示されない場合

分割処理の完了後、保存済みの素材一覧・試聴用音声・ログを別の画面更新処理で
自動的に読み込みます。「素材一覧を再読み込み」でも再取得できます。
このボタンは未保存の表の編集内容を保存済みの内容で置き換えます。
既に分割したプロジェクトは「保存済みプロジェクト」から選択し、
「保存プロジェクトを開く」で読み込めます。分割をやり直す必要はありません。

起動時は最初の保存済みプロジェクトとそのIDを同時に表示します。
「保存プロジェクトを開く」は一覧の選択を優先するため、IDが空でも開けます。

### v0.1.1 自動分割の改善

文末の後に0.65秒以上の間がある発話は、5秒未満でも独立した素材として保持します。
間の短い隣接文は、従来通り目安の長さに収まる範囲で結合します。
文末の句読点が単独・長さゼロのASRトークンでも、句読点と文境界を保持します。

切り位置はWhisperの単語時刻に加え、音声波形の静かな区間から補正します。
単語の外側・最大0.4秒の範囲だけを調べ、隣の素材との中間位置を越えません。
音量による補正なので、BGMやノイズで静かな区間が見つからない場合は従来の余白を使用します。
ASRが示す単語の範囲を削って無理に秒数へ合わせる処理は行いません。

新しい分割ロジックは更新後に「開始」で作成する新規プロジェクトから適用されます。
既存の素材・学習状態は変更しません。新旧を比較する場合は同じ元音声で新規プロジェクトを作成してください。
実音声での改善率は未計測のため、分割後は試聴して確認してください。

### 長い発話に句読点が付かない場合

早口などでWhisperの文字起こしが句読点を省いた場合、最後の疑問符まで
長い1素材として残ることがあります。20秒と最大秒数の2倍のうち大きい値を超える
区間に限り、「です」「ます」「ください」などの文末表現と0.2秒以上の間が
一致する場所を分割候補に追加します。時間だけで強制分割はしません。
「です」が直後の「が」などに続く場合は候補から除外します。
元から短い区間はこの補完処理の対象にしません。
推定した境界には「句読点不足・文末表現と間から分割（要試聴）」と表示します。
文末表現の推定は簡易的なため、最後に試聴して確認してください。

検証では、提供された54.56秒の早口の日本語音声をlarge-v3（CPU / INT8）で
認識し、従来約51秒の1素材だった区間が、調整後は7素材（約4.2〜11.6秒、
前後の余白を含まない）になりました。この1例での確認であり、すべての音声で
同じ精度を保証するものではありません。ASRの単語時刻と認識文は
各プロジェクトの `asr/000.words.json` などに保存され、ZIP書き出しにも含まれます。

### 素材一覧とログの表示更新

開始時にプロジェクトIDを先に確定し、長時間処理とは別に2秒ごとに
保存済み素材一覧とログを読み込みます。処理終了時の画面更新を受け取れなくても、
保存が完了した素材を表示します。保存内容が変わらない限り、編集中の表や
選択中の試聴クリップは上書きしません。更新後はターミナルを終了して
`start.bat`で起動し直し、ブラウザも再読み込みしてください。
分割済みの素材は保存済みプロジェクトから開けるので、再分割は不要です。
